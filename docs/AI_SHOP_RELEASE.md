# AI Shop release contract

Decision date: 7 October 2026. Route: `/ai`. Existing hardware shop: `/shop`.

## Result

The AI collection adds an immediately useful original product to the existing Starlight Technology buying-intelligence surface. Visitors can download four editable planning files, choose a job/data boundary/starting point, and export the resulting plan as Markdown. The planner is deterministic and makes no model or provider requests. Software references connect each tool to a job, stop condition and complete cost boundary. Hardware purchasing decisions remain in the existing Studio Shop.

Paid Workflow Edition, Local AI Lab and maintained agent kits remain proposed. There is no payment CTA, Product/Offer schema, account creation or promise of delivery for them. The free kit is CC BY 4.0 for original Starlight text. Third-party software, models and source content are not redistributed.

## Three grounded visual options

1. **Workshop brief — selected.** Continue the live black/lime industrial editorial language. Put an actual readable decision artifact in the first viewport: job, permission boundary and acceptance proof. Extend the existing typed evidence and system-board composition to original downloadable material. Calm, functional depth comes from hierarchy and the physicality of a single brief sheet, not effects. This is the recommended route because it reinforces the existing shop and delivers an artifact immediately.
2. **Field manual.** Use the existing mono metadata, article components and lime verdict panels as a more text-led operating manual. A large annotated brief opens the page; software appears as structured rows. Suitable for returning technical operators and long reference reading, but offers a weaker first impression of the original free product.
3. **System assembly.** Reuse the existing original category schematics and system-planning shortlists to make a local-AI system the hero: runtime, compute and recovery. Suitable for hardware-led campaigns and machine comparison traffic. It would overweight procurement for this release, whose ready product is an editable workflow brief.

No new design identity, stock hardware imagery, decorative node network, fabricated dashboard, vendor logo licence assumption or generated product screenshot was introduced. The brief object is original semantic HTML labelled as illustrative fields; the downloadable example is explicitly fictional and unrun.

## Delivery and data flow

- Static `/ai` server component owns content, canonical metadata and CreativeWork/DigitalDocument structured discovery.
- Only the three-select planner is a client component. State is transient and not persisted.
- The browser turns deterministic planner output into a local Markdown download. It creates no customer record.
- Public downloads are static repository files. No provider credentials, personal information or private datasets are accepted.
- Existing site-wide Vercel Analytics and Speed Insights remain as previously configured; no new tracking event or vendor is added.

## Release gates

Run the repo's locked toolchain verification, lint, typecheck, Vitest, editorial planner tests and production build. Then inspect exact candidate `/ai` and homepage in desktop/mobile browser layouts, including all selects, download action, keyboard focus, anchor offset, mobile menu and width overflow. Record actual evidence in `design-loop-evidence.json`; an unperformed review has no numeric score. The repo requires at least 26/30, and the current canonical flagship web gate requires 28/30 plus its independent evidence bundle.

The pre-existing Studio Shop release evidence stays in `docs/evidence/studio-shop/release.json`. A new AI-specific root record supersedes the latest pointer without borrowing the prior release's scores or observations.

## Readiness and rollback

Ready after the exact candidate passes its gates: static free materials, deterministic planning, provider documentation references and existing hardware links. Pending: preview browser review and corresponding design score until observed; paid product installations, support contracts, checkout/fulfilment, partnership acceptance and any scheduled operations.

The current browser tool can inspect desktop but exposes no supported viewport resize or mobile emulation. A mobile capture attempt was blocked by its local-file navigation policy. Responsive source review cannot substitute for an actual mobile capture; the mobile release gate remains pending. No alternate browser or fake viewport evidence is used.

## Existing commerce correction

The prior `/pricing`, `/offers`, `/app` and `/success` surfaces advertised memberships and immediate fulfilment that the implementation did not provide. The change preserves product scope and proposed prices, but marks self-serve paid offers unavailable, changes purchase CTAs to scope inspection and removes unconditional purchase-success/activation claims. `/checkout/[sku]` cannot use an environment URL as proof of product readiness. B2B architecture keeps an explicit scope-inquiry path before any agreed engagement and invoice. No account, receipt or payment is fabricated.

Interface text keeps authored case rather than forcing uppercase through global CSS. Existing explicit brand and short metadata strings retain their authored form. The intermediate navigation breakpoint accounts for the added AI Shop link.

Release through a draft PR and the existing GitHub/Vercel native integration. Rollback reverts this PR: remove `/ai` and public kit downloads and restore nav/home/sitemap/llms entries and the previous design evidence pointer. No order, payment, account, provider credential, database migration or background job is introduced, so rollback has no financial or customer-state migration.
