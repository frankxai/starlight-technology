# XR device intelligence: operating model

Canonical consumer path: `starlight.technology/xr`. FrankX `/stack` is Frank's personally used setup and should link to the XR register when relevant. Keep one public, source-backed device record in `src/lib/xr-catalog.ts`; this public repository is the open contribution surface for now. A separate dataset repo or subdomain needs a demonstrated external API or contributor use case.

Each record names class, status, manufacturer claim, intended job, wrong-purchase condition, complete-system boundary, primary source, check date and an official destination. Recommendations derived from these records are labelled inference. Manufacturer specifications are not hands-on results. Recheck before changing launch status; archive or mark stale records where a verification fails. For price or stock, record locale, merchant, original source, currency, timestamp and a compliant refresh schedule before display.

## Merchant link gate

1. Official product links are editorial sources, not affiliate links. Never insert an affiliate identifier without the merchant programme's approval and a visible relationship label near the offer.
2. Amazon Associates: enrol the exact site and regional programme first. Use an authorised product link or approved widget. Show Amazon prices or availability only with Amazon-served content or the authorised API under its current rules. Do not scrape or copy Amazon images to the open dataset. Keep licensed commercial content out of any model training or public export.
3. Direct manufacturer affiliate: check that the manufacturer actually offers a regional programme, obtain approved creatives/link formats and represent commission accurately. A normal Meta Store link is not evidence of a Meta hardware affiliate relationship. Meta's Quest app referral programme concerns apps, not a general hardware affiliate arrangement.
4. Rank by user workflow and evidence before commercial destination. No commission-based suppression of non-paying alternatives. The current XR page has only direct, non-affiliate manufacturer links.

## Experience and agent contract

The `/xr` decision studio is an executable, inspectable decision model. It asks for the job, timing and available host. It returns a named device, the rule behind it, a blocking constraint and next actions. Share links encode only those three non-sensitive choices in URL parameters; no profile or conversation database is added.

- `GET /api/xr/catalog` exports dated evidence records for external builders and future Explorer skills.
- `GET /api/xr/decision?goal=prototype&timing=now&host=laptop` exports the same recommendation logic as the UI, tagged as inference.
- `POST /api/xr/ask` accepts one bounded question and a selection. The default is a deterministic cited catalog answer. It stores no conversation. The optional AI Gateway path is enabled only when `XR_AI_ENABLED=true`, `AI_GATEWAY_API_KEY` and `XR_AI_MODEL` are set. A model failure falls back to the catalog answer. Source URLs are supplied by the server, not generated by the model.
- Before switching on public AI, configure a Vercel firewall rate rule and a spend ceiling. The route limits input length, output tokens and execution time, but serverless instances cannot enforce a global quota on their own. Estimate monthly cost from measured input and output tokens per response and a bounded request allowance. No user prompt is sent to Gateway in the default configuration.
- Treat generated text as source-guided synthesis, not proof; it cannot validate device comfort, regional stock, prices or unpublished SDK support. Confirm these with primary sources or hands-on testing.
